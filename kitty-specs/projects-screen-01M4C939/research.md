# Research and decisions: Projects screen

Decisions D-01 onward, numbered afresh for this mission. Each has the choice, the alternatives and the reason. Facts about existing code were read on `main` at `ad94164`.

## Decisions

- **D-01 Two elements, one shell value.** `sk-projects-screen` and `sk-open-project-dialog`, plus `layout="picker"` on the shell (ruled Q1 and Q3). Alternatives: a screen that owns its top bar (rejected by Q1: duplicates top bar, skip link, tier handling); the dialog inside the screen (rejected by Q3).
- **D-02 The shell value, not a property.** `ShellLayout` is a closed union that falls back to `project` for unknown values (`sk-mission-shell.ts` `render()`). A third value is additive on an existing property and names a chrome, not a pipeline. The rendering rules are in `contracts/shell-picker-layout.md`. Alternative: a boolean `no-nav` property (rejected by the ruling: no new property).
- **D-03 Name `picker`.** The prototype calls the container `project-picker`; the value says what the chrome is for and not what the screen is called (`projects`, which would invite a "projects" sidebar item). Alternative names `bare`, `top-bar-only`: `picker` is shorter and used by the prototype. Squad may rename; it is the only place the name is written (`shell-types.ts`).
- **D-04 Entry resolution is a pure function.** `resolveEntry(entry, listStatus)` returns one of `row`, `loading`, `error`, `unavailable`. Whole-list `status` is handled before it (the list-level states replace the list). An entry with `state` set wins over a present `project` (ruled Q10). Test: every combination, with a foreign `health` value.
- **D-05 Health is data.** `HEALTH_BADGES` in `defaults/health.ts` maps the two contract values to `{ label, tone }` (`healthy` success "healthy", `schema_drift` attention "schema drift"); anything else renders `{ label: raw, tone: neutral }`. A `labels.health` hook is consulted first. The data-driven gate reads `ProjectHealth.yaml` from the vendored schemas (a re-vendor that adds a value widens it with no edit). `healthy` is a common identifier, so it joins the comparison-only bare words (as `fresh`, `stale`, `changed`); `schema_drift` is an underscored literal. This is NOT free of an edit: the config's list of bare words is a literal (`['changed','unknown','fresh','stale']` filtered by the enums read), so IC-02 adds `healthy` to it and reads `ProjectHealth.yaml` into `NEW_ALL`; without the edit `healthy` would be matched as a literal anywhere, which is stricter than intended. A later re-vendor that adds a third health value widens the gate with no edit (as a literal match).
- **D-06 No verdict from `schemaVersion`.** The view model has no `schemaVersion` field except the accessible description string (ruled Q4). A test with `schemaVersion` present and `health` unexpected proves the badge follows `health` only.
- **D-07 Version word.** `versionText(v)` returns `null` for null, else `VERSION_PREFIX + v` where `VERSION_PREFIX` is "v" in `defaults/projects-copy.ts` (G-8). A value that already starts with "v" is still prefixed ("vv1"): the contract pattern allows a leading letter, and the screen does not parse the string.
- **D-08 Location line.** One mono line: `location` verbatim, then ` · ` + branch when `currentBranch` is non-null, then ` · local only` when `localOnly`. The separator is `SUMMARY_SEPARATOR` from `defaults/lanes.ts` (already the middle dot). If `location` is absent (error/unavailable entry without text) the line shows only the segments that exist.
- **D-09 Mission count and entry count words.** `missionCountText` (exists, `defaults/missions-copy.ts`) for rows. `projectCountText(n)` new: "1 project", "N projects", "0 projects" hidden while the list loads or is in error (the toolbar shows no count then).
- **D-10 Active-ago.** `resolveActivity(iso, now, hooks)` from `logic/time.ts` unchanged; the row text is "active " + that, except the no-activity text and the just-now/yesterday forms which already read naturally. A `now` earlier than `lastActivityAt` reads "just now" (the helper treats negative delta as under a minute). Offsets are compared as instants by `Date.parse`.
- **D-11 Row control (drift DP-26).** Openable rows are one focusable control (the whole row is the target, as the prototype's `<a>`). Because the screen does no navigation, it is a `button`-semantics control or a link with `href`? The prototype's `<a href>` navigates; here the host routes on the event. A real `<a>` without `href` is not focusable. Decision: the row is a `button` role-less element drawn by the library button if spike S1 shows the library can carry the row chrome, otherwise a raw `button` under E-31's allowance with `type="button"`. A link would invite open-in-new-tab semantics the screen cannot honour. The accessible name reads name, health and Mission count (the version, location and activity are the description). Alternative: `role="link"` on a `div` (rejected: ARIA reconstruction of native semantics).
- **D-12 Arrow.** The "→" stays inside the muted side text for openable rows only, `aria-hidden` (DP-7).
- **D-13 Loading, error and unavailable rows.** Same box as a row (so the list does not jump), with the name (when the host gives it, else the location's last segment is NOT derived: the screen never parses a path) and location, and a state line. `loading`: `aria-busy="true"` on the row and a busy indicator from the adopted `progress` family; `error`: the generic sentence and a secondary `sk-button` "Try again" with the accessible name including the project name; `unavailable`: the word and nothing else. An entry without a `name` is shown by its `location` alone; if both are absent, by a generic "Project" word from `defaults/` plus its position. The host wrapper therefore carries `name?` (optional display name) beside `project`. Added to data-model; Q10 allows it (the issue's "name and location kept" needs a name when `project` is null).
- **D-14 Live region.** One polite region, text from the state actually shown: "Loading projects", "N projects", "No recent projects", the error sentence. Per-entry transitions announce "<name> loaded" or "<name> could not be read" only for an entry whose kind changed since the previous render (tracked by `key` in a private map, replaced on every update). Mismatched or late data counts as not loaded: an entry whose `project.name` is empty is treated as `error`.
- **D-15 Focus capture.** As the shipped rule of `sk-work-package-screen.ts`: on EVERY update, `willUpdate` records `shadowRoot.activeElement`; `updated()` moves focus to the `h1` (made programmatically focusable) only when the recorded node is gone, else leaves focus alone. Test per transition (loading to ready, ready to error, entries replaced, a focused retry button whose entry becomes ready).
- **D-16 Dialog open/close.** Native `dialog.showModal()` / `close()` from the `open` property in `updated()`. Native `cancel` (Escape) and a backdrop click (`event.target === dialog`) set `open` false. Focus return captured in `willUpdate` when `open` changes to true: the deep `document.activeElement` (walking shadow roots). Returned in `updated()` after close if `isConnected`. Why not the prototype's `form method="dialog"`: the dialog is a shadow-DOM element and the host drives `open`; a form submit would bypass the property.
- **D-17 Listbox model.** `role="listbox"` with `aria-label`, options `role="option"` raw buttons (E-33), roving tabindex on the selected option or the first, ArrowUp/ArrowDown/Home/End move focus only; Enter or Space selects (emits `sk-browse-folder`); the host answers with new `location`, `folders` and `selected`. Selection is therefore controlled by `selected` (a folder `location` or null). The parent row is an ordinary option with `kind: 'parent'`.
- **D-18 Open enablement.** Open is a primary `sk-button` with `disabled` unless the selected folder has `valid: true`; a visually-present hint line states why ("Select a folder that is a valid project"). `aria-describedby` points at it. Event payload `{ location }` is the selected folder's host `location` (opaque).
- **D-19 Dialog states.** `status` is the folder listing's view state: `loading` (busy list), `error` (alert notice with retry, `sk-retry-load` `{ target: 'folders' }`), `empty` (a folder with no sub-folders: the empty-folder word), `ready`.
- **D-20 Retry union.** Three new members: `ProjectRetryDetail { target: 'project'; key: string }`, `ProjectsRetryDetail { target: 'projects' }`, `FoldersRetryDetail { target: 'folders' }` appended to the one union. The builder takes the entry `key`; an entry without a `key` is inert (retry control not drawn).
- **D-21 Fixtures.** Contract examples by name (`Project.example`, `Project.schema-drift`, `Project.all-null`), plus host overlays: `loading`, `error`, `unavailable` entries, `long` (255-char branch, 64-char version, long name and location), `null-version`, `unknown-health` (a value outside the enum; the generated Project type forbids it, so this is a host-typed relaxation like #5's `*-open` relaxations), `fifty`. Locations are `~/work/<synthetic-name>`. Names: synthetic (`example-app`, `demo-service`, `sample-docs`), not the prototype's.
- **D-22 Stories and baselines.** About 24 screen stories and 8 dialog stories; a tier suffix tag (`vw-<n>`) per the harness; baselines only in IC-08.
- **D-23 Exceptions.** E-31 row chrome, E-32 dialog chrome, E-33 option paint, E-34 class-only families, all conditional on the spike evidence (a spike that proves a library element carries the look deletes the exception, as #5's E-19 (a) and E-20 were).
- **D-24 Pill ellipsis.** The health pill and the "local only" pill use the one shared rule (full text in `title` and in the accessible name); no new rule.
- **D-25 Dialog placement.** The dialog is a sibling the host places in the page, not a child of the screen (ruled Q3: separate, optional). In stories it is rendered beside the screen in `shellFrame`.
- **D-26 `localOnly` and branch pills?** The prototype draws them as part of the mono line, not as pills. They stay text.

## Risks

- **R-1 Re-vendor breakage.** The five new required `Project` members break any literal typed `Project`. Known sites: `sk-missions-screen/fixtures.ts` (spreads the contract example, so it follows), tests in `defaults.test.ts` and `sk-missions-screen.test.ts`. IC-01 fixes them and runs typecheck.
- **R-2 Gate coupling.** The data-driven gate reads schema files by name; a renamed schema in the merged contract breaks the config at load. IC-01 runs `pnpm lint:data-driven` straight after the re-vendor.
- **R-3 #7 merge.** The retry union moves; the plan re-checks at IC-02 dispatch (Build base item 2).
- **R-4 Dialog top layer in the visual harness.** If S2 shows the harness cannot capture it, IC-08 adds a harness tag; this is the one possible change to shared test tooling.
- **R-5 Parallel missions.** Drift and Ops edit `src/index.ts`, `defaults/index.ts` and the retry union; all three appends are one-line and conflict only textually.
