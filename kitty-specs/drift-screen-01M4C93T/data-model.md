# Data model: Drift screen

Types come from the vendored contract (generated by `pnpm contract:generate`); the view types below widen them only where the
screen must accept foreign values (the data-driven rule), as #4 and #5 do with `WorkPackageRecordView`.

| Type | Source | Definition |
|---|---|---|
| `DriftReport`, `DriftFinding`, `LaneComparison`, `DriftRefusal` | generated (`types.generated.ts`) | strict, closed |
| `DriftFindingView` | `src/contract/types.ts` | `DriftFinding` with `kind`, `severity`, `authority`, `derivedSide`, `remedy`, `sourceCode` and the two lane fields widened to `string` (`remedy` and the lane fields stay nullable) |
| `DriftReportView` | same | `{ scannedAt: string; findings: DriftFindingView[]; truncated: boolean }`; assignable from `DriftReport` |
| `DriftFindingKey` | same | `{ missionId: string; kind: string; artifactPath: string }` |
| `DriftMissionName` | same | `Pick<MissionHead, 'missionId' \| 'slug' \| 'friendlyName'>` (contract field names, as `WpScreenMission`) |
| `DriftStatus` | `view-state.ts` neighbour | `ViewState \| 'not-found'` |
| `FindingView`, `LaneRowView` | `logic/drift-finding.ts` | see `contracts/sk-drift-screen.md` |

## Identity and ordering

- The key is (`missionId`, `kind`, `artifactPath`); `sameKey(a, b)` is exact string equality on all three.
- The list is drawn in the report's array order; no function in `logic/` sorts, groups or filters findings. A test pins that the
  rendered order equals the input order for a deliberately unsorted fixture.
- The Lit `repeat` key of a row is `${missionId}|${kind}|${artifactPath}` (a duplicate key, a contract violation, gets the index
  appended by `rowKeys(findings)` so Lit never drops a row).

## Derived values (display only, C-004)

- `count = findings.length`; `rollup` = per-severity tallies in first-seen order; `hasDanger` = any shown finding whose severity
  maps to the `danger` tone in `SEVERITY_WORDS`/the `severity` hook. No `kind` is read for counting.
- `agrees(report, missionId)`: when `missionId` is non-empty, every finding's `missionId` equals it. Otherwise true.
- `effectiveState(props)`: `loading` when `status` is `ready` and `report` is null or its `findings` is not an array, or `ready` with a scoped disagreement;
  `empty`-look when `status` is `empty` or (`ready` and `findings.length === 0`); else the given status.
- `selectedIndex` = index of the first finding with the key of `selectedFinding`, else -1.

## Fixtures (generated or overlaid; names in `fixtures.ts`)

Contract-derived: `reportPopulated`, `reportClean`, `reportCorruptJson`, `reportTruncated`, `refusalMissionNotFound`,
`refusalScanUnreadable`. Overlays (each through the registry, kind `relaxed` or `host`): `reportUnknownKind`, `reportUnknownSeverity`,
`reportUnknownAuthority`, `reportUnknownRemedy`, `reportUnknownSourceCode`, `reportOneSidedLane`, `reportManyLanes` (40 rows),
`reportLongSlugMission` (host names map), `reportMissionUnlisted` (host), `reportScoped`, `reportScopedForeign` (host),
`report1000` (bulk generator, `truncated` true). The relaxation `drift-vocabulary-open` widens the five enum fields (`kind`, `severity`, `authority`, `derivedSide`, `remedy`) and the two lane fields (`sourceCode` is a pattern, not an enum, so an unknown code needs no widening); reverted-must-fail proof in `check.mjs` like the other relaxations. Mission slugs and ids are synthetic; no path, e-mail
or account name (NFR-007).
