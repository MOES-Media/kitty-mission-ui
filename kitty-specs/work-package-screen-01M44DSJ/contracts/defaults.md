# Contract: new default modules (`src/defaults/`) and logic (`src/logic/`) of this mission

Plain TypeScript, no I/O, no DOM. Extends #4's `contracts/defaults.md`, which is reused unchanged by import: `lookup`, `LANE_LABELS`, `STATE_BADGES`, `NOT_STARTED_BADGE`, `STALE_BADGE` (`defaults/lifecycle.ts`: `{ label: 'stale', tone: 'info' }`), `LANE_COUNT_TEXT` and `SUBTASK_PROGRESS_TEXT` (`defaults/lanes.ts`), the `StateBadge` and `BadgeTone` types (`logic/types.ts`), `resolveStateBadge`, `resolveLaneLabel`, `relativeTime`, `resolveActivity`, `formatWholePercent`. Nothing of those is redeclared here: the word "stale" and its tone, the "N Work Packages" text and the subtask progress text each keep one home. New files are re-exported from `defaults/index.ts` (the one edit of that file, IC-02). Every table is a `Readonly<Record<string, T>>` read through `lookup`; a value that is not a key shows raw (FR-023). English copy only; nothing here is a lane or phase. Badge tables are typed `Readonly<Record<string, StateBadge>>`: one table per vocabulary (word and tone together), and every resolver returns a `StateBadge`, so no untyped tone string exists and no cast is needed before `sk-pill-tag`.

The plan-phase forks are ruled (operator, 2026-10-05; `plan.md`, "Rulings applied"); the text below is the ruled text.

## `defaults/staleness.ts`
The "stale" badge is #4's `STALE_BADGE` (imported, not redeclared). `STALENESS_MINUTES_TEXT` (`(minutes: number) => string`: "N min since last commit" with `N` as given), `STALENESS_REASON_WORDS` (`planning_artifact_repo_root_shared_workspace` "shares the repository root, no worktree to measure", `live_claim_process` "the claiming process is alive"), `FRESH_TEXT` ("recent work"). The status words `fresh`, `stale`, `not_applicable` are table keys read via `STALENESS_STATUS_ROLE` (a record from status to `'badge' | 'row' | 'none'`), so no comparison with a status literal exists in a part. A status that is not a key of `STALENESS_STATUS_ROLE` resolves to role `'row'`: a quiet Facts row showing the raw status text, never nothing and never the word `undefined` (FR-023: an unknown value is shown, not dropped). A known `reason` that is not a key of `STALENESS_REASON_WORDS` shows raw. `not_applicable` keeps its visual silence (Q1) and meets NFR-011 with visually hidden text in the Facts panel (operator ruling 2026-10-05, VISUAL-014 (a)): `STALENESS_NOT_APPLICABLE_TEXT` is `(reason: string | null) => string`, "Staleness: not applicable, <reason>" with the reason through `STALENESS_REASON_WORDS` (raw fallback; a null reason drops the clause), drawn with `visually-hidden.ts` and asserted by a DOM text query (WP-21b).

## `logic/` additions (each with its own unit test file)
| Function | File | Signature | Behaviour |
|---|---|---|---|
| `resolveLists` | `wp-lists.ts` | `(wp: WorkPackageRecordView, detail: WorkPackageDetailView \| null) => ResolvedLists` | data-model.md: one source per list; a detail whose `wpId` differs from `wp.wpId` is treated as omitted and returned as `detail: null` |
| `joinHandles` | `wp-actor.ts` | `(actor: Actor \| null) => string \| null` | non-null handles joined by `:` |
| `resolveVerdict` | `wp-review.ts` | `(verdict: string \| null) => StateBadge` | `lookup(VERDICT_BADGES)` then raw (label = the raw value, tone `neutral`); null gives `NO_VERDICT_TEXT` neutral |
| `resolveChangeState` | `wp-files.ts` | `(state: string \| null) => StateBadge \| null` | null gives null; an unknown key shows raw neutral |
| `filesView` | `wp-files.ts` | `(files: ResolvedFile[]) => FilesView` | reads `UNKNOWN_CHANGE_STATE`, no literal; `FilesView = { allUnknown: boolean; rows: ... }` (see data-model.md) |
| `stalenessView` | `wp-staleness.ts` | `(s: Staleness \| null \| undefined) => { role: 'badge' \| 'row' \| 'none'; ... }` | via `STALENESS_STATUS_ROLE`; unknown status gives the `'row'` role with the raw status text |
| `historyView` | `wp-history.ts` | `(history: HistoryEntryView[], hooks, now) => HistoryItem[]` | array order; last entry `current: true`; forced and reason as given; raw lane fallback |
| `retryDetail` | `wp-retry.ts` | `(target, props) => SkRetryLoadDetail \| null` (null when there is no Mission or no id anywhere: the control is inert and no event is built) | payload builder (one place): `wpId` from the property, then `workPackage.wpId`, then `detail.wpId` (operator ruling 2026-10-05, ARCH-013 (a')); one test per branch |
| `resolveRefusal` | `wp-retry.ts` | `(code: string \| null) => string` | `lookup(DETAIL_REFUSAL_WORDS, code) ?? code`; null gives `DETAIL_REFUSAL_GENERIC`; the code comes from the `detailRefusalCode` property |

All new logic files sit under `src/logic/`, which the `data-driven` gate scans: no lane, phase, verdict, change-state or staleness-status literal may appear there. The `data-driven` gate covers the verdict, change-state and staleness words (IC-02 extends `eslint.data-driven.config.mjs`, operator ruling 2026-10-05, ARCH-006 (A)); refusal codes and the artifact kind are covered by the reviewer self-check list and the foreign-value tests.
