# Contract: `sk-work-package-screen`

Screen contract (`@screen`), file `packages/mission-ui/src/elements/sk-work-package-screen/sk-work-package-screen.ts` with private fragments `header-parts.ts`, `facts-parts.ts` (Facts, Assignment, Frontmatter), `files-parts.ts` (Owned files), `history-parts.ts`, `review-parts.ts`, `chain-parts.ts` (evidence chain, dependency chain), `work-parts.ts` (Subtasks, Workspace, artifact links), `state-parts.ts` (whole-screen and detail regional states, and the one shared regional empty-form helper), `panel-parts.ts` (the panel wrapper over `sk-card` and `sk-section-header`), plus `fixtures.ts` and stories. No I/O, nothing stored. Decisions: `research.md` D-01 to D-08, D-13, D-14. Surface frozen by IC-03b (manifest regeneration); the file is not edited for the surface afterwards.

The plan-phase forks are ruled (operator, 2026-10-05; `plan.md`, "Rulings applied"). Wiring (ARCH-003 (A)): IC-03b creates every part file as a stub with the final signatures of "Part signatures" below and wires all stubs, the composed `static styles`, the status and regional-notice switches and the adopted sheets (`library-sheets.ts`) into the screen file; region WPs replace stub bodies only.

**Panel and region ownership (one rule).** IC-03b (WP04) draws, in the screen file, EVERY element that carries a `data-region` id EXCEPT one: the header band of the data-less `loading` and `not-found` states, which `state-parts.ts` (WP08) draws (the element carrying `data-region="header"` with the complete `renderBreadcrumb` and the `h1`; it never calls `renderHeader`, so chain Y needs nothing from chain X). The screen file draws: each titled panel through `renderPanel(id, title, body, options?)` (`panel-parts.ts`, complete; titles are constants of `defaults/wp-copy.ts`), and as plain wrapper elements the header band (`header`), the two inner wrappers of the Review panel (`review-summary`, `review-cycles`), the cancellation notice (`cancellation`), the artifact-links actions group (`artifact-links`, not a panel: quiet buttons without a title, as the prototype shows them) and the regional notice (`detail-notice`). A part renderer returns the BODY of its region only (the content inside that element): it never calls `renderPanel`, never writes a `data-region` attribute (the one exception is the `state-parts.ts` loading and not-found header above) and never decides whether its region is drawn. The screen decides that from the region's `<Region>View`: each view builder in the screen file returns `null` for the contract's 'not drawn' form (column 'Drawn when' of the table "Containers and drawn-when", below) and the screen then draws nothing for the region (no container, no heading, no label text); a non-null view always gets its container, so a stub (it returns `nothing`) leaves an EMPTY container with its id and, for a panel, its heading, never a missing one. The Review panel carries no id of its own (`renderPanel(null, REVIEW_TITLE, body)`); it hosts the two wrappers above. Region WPs fill bodies and prove presence and absence through the screen's DOM; a drawn-when rule they find wrong is a change request to the orchestrator, not an edit.

The screen follows the enclosing `sk-mission-shell`, including across shadow roots: a wrapper element that holds the screen in its own shadow root does not hide the shell, and the screen reads the shell's reflected `tier` through the wrapper's host (pre-merge squad, BOUNDARY-005). The shell documents `tier` as public on its `tier` property (so the manifest carries it on the attribute).

Every `display: grid` stack (the column stacks) declares `grid-template-columns: minmax(0, 1fr)`, or an unbreakable word widens the whole column (spike S9 lesson; the prototype's `.stack` lacks it); the skeleton test names it.

## Announcements (one polite live region, visually hidden, `visually-hidden.ts`)

The screen has exactly one status region. It announces text that names the Work Package, once per transition, never on first render:

| Transition | Announcement |
|---|---|
| first render (any state) | nothing |
| `status` becomes `loading` after first render | `announceLoading(wpId)` |
| `status` becomes `ready`, or the SHOWN Work Package changes while `ready` (the `wpId` of `workPackage`, whatever the `wpId` property says: landing CORR-002) | `announceLoaded(shown id)` once; a property refresh of the same Work Package announces nothing. Setting the `wpId` property alone, while `ready`, renders `loading` (see Properties) and announces `announceLoading` |
| `status` becomes `ready` together with `detailStatus` `error` or `not-found` | ONE line, `announceLoadedDetailUnavailable(wpId)`: "Work Package WP04 loaded. Work Package detail unavailable" (landing CORR-005), so the refusal is not lost behind "loaded" |
| `status` becomes `error` | nothing from the region (the assertive alert notice is the only announcer) |
| `status` becomes `not-found` | `announceNotFound(wpId)` |
| `status` becomes `empty` or `nothing-selected` | nothing (static content) |
| `detailStatus` becomes `loading`, then `ready` | `ANNOUNCE_DETAIL_LOADING`, then `ANNOUNCE_DETAIL_LOADED`, one line each |
| `detailStatus` becomes `error` or `not-found` | `ANNOUNCE_DETAIL_UNAVAILABLE` once; the regional notice carries no live role of its own, so nothing is announced twice |

## Behaviour rules (tested)

- Focus (landing CORR-003): on EVERY update the screen captures the element that has focus inside its shadow root; after the update, only when that element has been detached by it (a status or detail state change, a `ready` screen turning `empty`, a Work Package swapped under the same `wpId`), focus moves to the `h1`, or to the root element (`tabindex=-1`) when no `h1` is drawn. An element that survives the update keeps focus. No property and no event.

- One source per list (`resolveLists`, FR-004). No arithmetic (C-004). No lane, phase, verdict, change-state or staleness literal in the screen (D-07). History in array order; "Current" on the last entry (D-08).
- A null `statusLane` gives a "not started" badge, the empty-history form and no actor (FR-021). An unknown lane value is shown raw (FR-023).
