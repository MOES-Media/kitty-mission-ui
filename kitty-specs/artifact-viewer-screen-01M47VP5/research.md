## Decisions

### D-01 One public element and private parts
`sk-artifact-screen` plus private parts (`toolbar`, `tab`, `document`, `source`, `refusal`, `inspector`, `state`, `prose-styles`: eight files). The renderer is not part of the element: it is `logic/markdown/render.ts`. Rationale: #4 and #5's recipe; the part file is the unit of write ownership. Alternative rejected: separate public elements for the document and the inspector (a second public surface for no reuse; the shell already splits tree and content).

### D-02 Reuse by import, never by copy
`LabelHooks`, `lookup`, `relativeTime`, `resolveActivity`, `StateBadge` and `BadgeTone`, `shellFrame`, the `classOnly` helper, `SkSelectWorkPackageDetail`, `SkOpenMissionDetail`, `visually-hidden.ts`, `progress-sheet.ts` and `OverflowRegion` (`overflow-region.ts`) come from #4 by import. `OverflowRegion` is the package's ONE overflow measurement (it makes a scroller a labelled, focusable region only while its content really overflows, measures on every host update and once more after the fonts are ready, because a size observer alone does not fire when only the content of an unchanged box grows); the Work Package board and the Pipeline screen already use it, so this screen builds no second detector (PLAN-FRESH3-001 (a), ruled 2026-10-06). It is extended by ONE named additive edit owned by IC-06b: several targets and both axes (the pane scrolls vertically, a table box horizontally), the default staying horizontal and single-target so the two present users and their tests are unchanged. `ArtifactKind` and the refusal codes come from the generated types and the vendored schema enums (`ArtifactKind.yaml`, `ArtifactRefusalCode.yaml`), never from the example files. `LabelHooks` itself is not edited: the artifact hooks are the separate `ArtifactLabelHooks extends LabelHooks` of `logic/artifact-types.ts`, so no shared line is a cross-mission merge point and the Missions and Pipeline screens do not gain hooks they never read.

### D-03 View states: `status` plus `contentStatus`
`status` is the listing's state (`loading`, `ready`, `empty`, `error`, `not-found`, `nothing-selected`); `contentStatus` is the open document's (`loading`, `ready`, `refused`, `error`). `nothing-selected` is derived by the host as `status: 'ready'` with no `selectedPath`; the screen ALSO derives it (a `ready` listing with an empty `selectedPath` shows "Choose an artifact" whatever `status` says), so the host cannot produce a blank pane. A content state never hides the tree (the tree is the shell's and is untouched by this screen's state). Refusals: `contentStatus: 'refused'` with `refusalCode`; a transport failure the host cannot code is `contentStatus: 'error'` with `errorMessage` and always offers Retry; the listing refusal `artifact_listing_unreadable` is `status: 'error'`; a listing 404 is `status: 'not-found'`. `status` is the four `ViewState` values of `view-state.ts` plus the two additions (one list, extended at type level); the screen has its own normalisers in `logic/artifact-status.ts` because #4's `normaliseViewState` knows four values: an unknown `status` collapses to `empty` (as the shell and #4, so a host bug is visible instead of an endless loading look), an unknown `contentStatus` to `ready`, an unknown `view` to `rendered`. What the pane shows for every combination, including a `ready` listing with a selected path and no content yet (the loading look), is the total table of `data-model.md`.

It holds BOTH detail types (`RetryLoadDetail`, moved from `logic/wp-retry.ts`, and this mission's `SkArtifactRetryDetail`), the union of them (`RetryLoadEventDetail`, a new name, because #5's `SkRetryLoadDetail` stays the alias of its own payload) and the single `declare global` whose entry is `CustomEvent<RetryLoadEventDetail>`; hosts discriminate on `target`. #5's names are kept as re-exports (`logic/wp-retry.ts` re-exports `RetryLoadDetail`; `sk-work-package-screen.ts` keeps its alias `SkRetryLoadDetail` and loses its event-map entry), so nothing in #5's tasks, tests or manifest text changes; this is the ONE named edit of #5's merged files, made by IC-06b on Base A (shared-files table of `plan.md`). A type-level assertion file under `packages/mission-ui/test/` (a `// @ts-expect-error` for a payload with the wrong `target`, compiled by `pnpm typecheck`) compiles only with the union, so reverting the decision fails the typecheck (the union is invisible to a run-time test). ### D-06 Renderer safety design (the core)
Contract in `contracts/markdown-renderer.md`. In one paragraph: markdown-it only PARSES (`md.parse(source, {})`); its `render`, `renderInline` and `renderer.rules` are never touched. The flattened token stream (every inline token included) is checked against the budget, then converted by `model.ts` to a closed discriminated union of block and inline nodes (headings 1 to 6, paragraph, bullet and ordered list with an integer start, list item, block quote, thematic break, code block, table with header and body cells and an alignment keyword, text, soft and hard break, inline code, emphasis, strong, strikethrough, link, image); any other token type, in particular `html_block` and `html_inline` (which `html: false` should never produce), throws `MarkdownUnsupported` and lands in the fallback (fail closed). `links.ts` classifies every link and image destination once, in the cached step, so `render.ts` only draws. `render.ts` turns the resolved union into Lit templates with an exhaustive `switch` and a `never` check; every tag name is a literal in a template; document data reaches the DOM only as (a) Lit text bindings and (b) the attributes of a fixed allowlist whose values are either keywords chosen by a `switch` (`data-align`), digits validated by `^[0-9]{1,9}$` applied to `String(start)` (`start`), or the `title` of an external link, an inert link or an image placeholder (the destination, truncated to a length from `defaults/`). No `class`, `style`, `href`, `src`, `srcdoc`, `id`, `name`, `on*` or `data-*` attribute value ever comes from the document. A code fence's info string is not shown and not stored (no `language-*` class, no label), because it is the one free-text field that has no visible purpose here. ### D-07 Parse cache, budget and fallback
`buildMarkdownModel(source: string, budget?)` is pure (it takes the source string, not the content object, and the budget member of the vocabulary, default `MARKDOWN_BUDGET`) and its result is cached by the screen in `willUpdate`, keyed by the VALUE of (`content.content`, `content.mediaType`) (a plain field, no timer, no storage), so a host that rebuilds the content object per render does not re-parse a 256 KiB document. Whether to parse at all is decided in `logic/` by `markdownFor(content)` (null unless the media type is the markdown constant), so the screen compares no media type. Two more caches sit in the same `willUpdate`: the path-to-kind map by listing identity, and the resolved tree by (model, open path, map) (`contracts/markdown-renderer.md`, Caches). Budget values live in `defaults/markdown.ts`: `maxSourceChars` 270000 (the contract's refusal line is 262,144 bytes before redaction; redaction can lengthen a short path into `[path]`, so the figure leaves headroom), `maxLineChars` 20000, `maxTokens` 60000, `maxDepth` 24, `maxNodes` 40000, `maxTableCells` 5000, `maxTextRun` 20000, `titleMax` 512, `maxDestinationChars` 2048, `maxAltChars` 512. A source over `maxSourceChars` or with a line over `maxLineChars` is NOT PARSED: it goes to the fallback with the reason `too-complex` (the pre-parse guards are the defence against quadratic shapes the parser might still have; no clock exists in the screen, so a time budget is impossible and a count budget is the substitute; the corpus adds a timing ceiling as a test, which may use a clock). `md.parse()` returns only block tokens and one `inline` token per paragraph, heading or table cell, so `maxTokens`, `maxNodes` and `maxDepth` are computed over the FLATTENED stream (every token and, recursively, every token of every `children` array); a scan of the returned array alone would see 3 tokens for a paragraph of nested emphasis that holds 160,000 inline tokens nested 40,000 deep (probe, 15.0.2). The check runs before the model recursion, and the recursion, like the nesting of the Lit templates, is bounded by `maxDepth`, so no stack overflow can occur outside the model's own try. A parse that finishes but exceeds a count, or whose maximum token `level` over the flattened stream exceeds `maxDepth`, falls back. markdown-it's own `maxNesting` is left at its default 100: it silently stops BLOCK nesting there (a block depth of 24 is reached first), but it does not cap INLINE nesting, which is why the flattened check exists. The fallback shows the attention `sk-notice` and the escaped source (a text binding in a `pre`), the Rendered tab labelled "Fallback". The three fallback reasons (`error`, `budget`, `too-complex`) share one notice sentence (DA-21); the reason is in `title` for diagnosis, as words from `defaults/`.

### D-08 Link and image rules
`classifyLink(destination, openPath, kindOf)` returns `{ kind: 'artifact', path, entryKind } | { kind: 'external', href } | { kind: 'inert' }` by the exact table in `contracts/markdown-renderer.md`, called by `resolveLinks` in the cached step (so `render.ts` imports `lit` only and the screen file does no second lookup). Two layers: markdown-it's default `validateLink` turns `javascript:`, `vbscript:`, `file:` and non-image `data:` destinations into LITERAL TEXT before the model sees a link (probe, 15.0.2), which differs from the inert-with-title look of N-Q12 (amendment A-8); `classifyLink` is the second layer for everything it lets through, and a test asserts that `[x](javascript:1)` yields no `link_open`, so a loosened `validateLink` turns the suite red. Highlights: the input is markdown-it's `normalizeLink` output, never trusted further; any destination with a control character, whitespace, a backslash, a NUL or more than 2048 characters is inert; a scheme is matched case-insensitively against `defaults/markdown.ts` (`http`, `https` need `//` and a non-empty authority that contains no `@`; `mailto` must match `^mailto:[^?#\s]+$` with exactly one `@`, so a prefilled query is inert); protocol-relative `//host` is inert; fragment-only is inert; a relative destination is percent-decoded once in a try block (a failure is inert; a decoded control character is inert, a decoded space is not), split from its query and fragment (both dropped), resolved by the shared `resolveRelative` against the open path's directory with `.` and `..` handled, an empty segment, a trailing slash or a `..` above the Mission root inert, and must equal a listing path byte for byte; a leading `/` is inert. The external `href` emitted is the normalised string (scheme case kept), and it is UNTRUSTED: the host contract is stated in `contracts/sk-artifact-screen.md`, Events, and in the `@fires` text so it reaches the manifest (the host re-validates the scheme case-insensitively, never navigates its own window to it, and shows the destination first); an external link also carries the truncated destination in `title`. An image is NEVER an element: the text "Image: <alt>" (word from `defaults/`, `labels` hook, `alt` flattened from the token's children), plus, when its source classifies as external and it is not inside a link, the same control around the whole text; an image inside a link is plain text, and links never nest controls. Rendered links are `a` elements WITHOUT `href` (D-14).

### D-16 Tree: pure helper, shell-drawn
`buildArtifactTree(entries, options)` in `logic/artifact-tree.ts`: `{ selectedPath, expandedIds, hrefOf, hooks }` in, `{ nodes: TreeNode[], current: string }` out. A selection change still re-creates every row, so the focused row is gone and focus lands on the pane by rule 8's screen-side mechanism (recorded in `willUpdate`, applied after `updateComplete` plus one animation frame only when focus fell to `body`; PLAN-FRESH4-002 (a)); this is documented in `quickstart.md` and pinned by a test in IC-09. ### D-19 Test strategy (D-34 of #4)
The package's vitest runs in Chromium only (`packages/mission-ui/vitest.config.ts`: browser mode, one chromium instance), so every file under `packages/mission-ui/test/` is a browser test: the pure model and logic are tested there too (the "model twin" is the same assertions run on the model without mounting a screen, in the same Chromium project), the screen, the corpus walk and the interaction tests use `page.viewport` first. Tests that need the file system or a bundler are `node:test` files under `scripts/`, run by `pnpm test:scripts` (the `hygiene` gate): the bundle budget (IC-04) and the row-to-story test (IC-11); #5's `scripts/wp-story-catalogue.test.mjs` is the model for the latter, but on #5's tip it runs under `test:terminology` (`node scripts/terminology.mjs && node --test scripts/terminology.test.mjs scripts/wp-story-catalogue.test.mjs scripts/visual-tags.test.mjs`), which CI does not run, so this mission deliberately places `scripts/artifact-story-catalogue.test.mjs` in `test:scripts` (run by the `hygiene` gate) so that CI runs it: a new CI behaviour, not precedent (PLAN-FRESH4-010); source scans use `import.meta.glob('../src/**/*.ts', { query: '?raw' })` in browser mode, as `defaults.test.ts` does with the contract YAML (PLAN-TEST-001 (b) plus (c), ruled 2026-10-06; the `unit-tests` gate command is unchanged). IC-01b checks that the root `vite` programmatic `build` is importable. No assertion on a class name; every event test has a positive control (the same interaction with a deliberately wrong precondition emits nothing, or the other event); every "no X" test is paired with a test that X appears in a control rendering (R-08); revert checks per test file; no `setTimeout` waits (`updateComplete`).

Request absence (PLAN-TEST-003 (a)): the structural walk (no `img`, `src` or `href`, assertions 1 and 3 of the corpus) is the stated proof of NFR-005. A `<meta http-equiv="Content-Security-Policy" content="img-src 'none'; frame-src 'none'; object-src 'none'">` is inserted in the corpus test file's document before rendering, with a `securitypolicyviolation` listener (it fires without a network), and a positive control: a hand-built `<img src="http://example.invalid/x.png">` triggers the listener. The meta applies to the corpus test file only, because a meta CSP cannot be removed for the document. A resource-timing observer is NOT used (it cannot see pending or `data:` requests).

Timing (PLAN-TEST-008 (a), ruled 2026-10-06): the spec numbers of NFR-006 are HARD ceilings (500 ms for a 256 KiB document and for a 1000-entry tree, 200 ms for a re-render), each measured as the best of three runs after a warm-up, in Chromium (the engine that asserts them), by the test clock (never in the screen). Before the clock starts the test pins the expected branch: the 256 KiB document (`makeLargeMarkdown`, the large content of the stories) must resolve to `ok` with a block count above 0, and the over-budget document to `fallback`, so a fast fallback cannot pass the large-document check. The re-render claim is proved by a counted `parseTokens` spy: after N property changes that leave `content` unchanged the spy count is 1 (removing the cache fails it), plus the node identity of an unchanged rendered block. The spec numbers (500 ms, 200 ms) ARE the gate ceilings; there is no multiplier. A multiplier would be allowed ONLY as the numbered amendment A-10 (`plan.md`); CP-1 ruled on 2026-10-07 that A-10 is NOT written and there is no multiplier: a test over the spec numbers that fails is a finding that goes back to the operator and is never quietly relaxed. The markdown budget is the option O3 values (`maxTokens` 150,000, `maxNodes` 110,000, `maxTableCells` 32,000), and the ceiling test uses a document shape and a margin that do not flake, because inline-heavy 149k-token documents measured 437 to 512 ms against the 500 ms ceiling.

### D-20 Dynamic pipeline (spec section, restated for the plan)
Ruling (PLAN-DESIGN-022 (a), 2026-10-06; A-9): the surface carries ONE optional structural input, `vocabulary` (`ArtifactVocabulary | null`, default null meaning the `defaults/` values), so the spec's "a later pipeline must need no change to this element, only different props" holds for structure and not only for words. It covers the kind table (label and icon per kind), the kinds that link a Work Package, the container segment and token separator, the markdown media type and the budget (the copy is not a member: PLAN-FRESH4-007 (b)); the logic functions take it as an argument, and the `labels` hooks remain the string-level overrides on top. The type is written in `logic/artifact-types.ts` (IC-02) and its default is built from `defaults/` (nothing is duplicated). A partly filled `vocabulary` is completed PER GROUP against `defaults/` (PLAN-FRESH3-004 (b), ruled 2026-10-06): the five groups are the kind table, the Work Package link kinds, the container segment with the token separator, the markdown media type and the budget; a group that is present is used as given, whole and not merged key by key (so a kind table with only a thirteenth kind shows the twelve others raw), a group that is absent takes the `defaults/` value, and `{}` equals `null`. The argument claim above covers ONLY the functions that read a member of the vocabulary; `formatArtifactSize` (the size unit table), `resolveArtifactRefusal` (`ARTIFACT_REFUSALS`) and `countBidiControls` (the code-point list) read tables that are not members and take no `vocabulary`. A refusal code outside the seven is therefore not a vocabulary member: it goes through `labels.refusal(code)`, which replaces the eyebrow (the cause word) only, while its sentence stays the generic one and it is not retryable. Data in, nothing hard-coded: kind words and icons, refusal sentences, tab labels, budget, schemes and every copy line are `defaults/`, `vocabulary` or `labels`; the screen's structure follows `resolveArtifactView`, which branches on STRUCTURE (is markdown, is empty, is refused, is raw-only) not on kind or code values, except the two data-held facts the spec names: the markdown media type and the kinds that link a Work Package, both constants in `defaults/` and members of the vocabulary. Proof: IC-02's gate extension (mechanical), IC-10's foreign-vocabulary composition test (a thirteenth kind with its own icon, a different container segment, folder names no fixture has, a tab label from `labels`, a refusal code outside the seven through `labels.refusal`, and a type-level case that `copy` is not a member of the vocabulary, all rendered with the gate green and no change to the element), and the self-check list in `contracts/gates.md`. A later charter-driven pipeline (artifacts following doctrine packs) changes props, not the element.
