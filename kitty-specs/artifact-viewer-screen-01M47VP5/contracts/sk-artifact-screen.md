Tested with an unknown value per property (IC-02 for the normalisers, IC-06b for the element). The shell option `flush` is set by the host on `sk-mission-shell`; the screen pads its own inset parts.

## Slots and parts

No slots, no CSS parts. The skip link text "Skip to artifact" is the shell's `skip-link` slot, set by the host; in this screen's stories the `shellFrame` option `skipLink` (added by IC-06b, default unchanged) passes it, so a Tab-tagged baseline shows the registered text (DA-2, PLAN-FRESH4-011). The shell's skip link focuses the shell's own wrapper (`[data-focus-target]`, `onSkipLink` in `sk-mission-shell.ts`: a fragment link cannot reach an id inside a shadow root) and the screen takes no part in it: the pane is NOT the skip target and carries no id. The next Tab from the wrapper reaches the first control inside the screen.

## Layout (container thresholds; S-A6 measures, IC-06b writes)

The host `:host { container-type: inline-size }`. Thresholds are written in rem (container queries accept rem), so the column switch follows the reader's text size (NFR-004); the pixel figures convert at the default 16 px root. The two layouts are a COMPLEMENTARY pair on ONE threshold `<T>`, so no container width (a fractional one at browser zoom included) matches neither: `@container (width >= <T>)` is two columns `minmax(0, 1fr)` and the inspector track (E-28, 270 px), the inspector placed in the right-hand track by grid placement although it is FIRST in the DOM, and `@container (width < <T>)` is one column, the inspector first, flat top border. Ruling (PLAN-A11Y-001 (a), A-1): `<T>` is a content cell of at least 45 rem (720 px), ruled at CP-1 on S-A6 (2026-10-07), with NO `ShellTierController` for this rule, and which the shell's mobile tier (cell = viewport, below 720 px) can never reach; the 801 to 831 px viewport window of the collapsed tier (cell 689 to 719 px) is one column where the prototype is two, recorded as confirmed drift (DA-33).

The shell has THREE tiers, not two: expanded from a viewport of 1100 px (content cell = viewport minus 296), collapsed from 720 px (cell = viewport minus 112) and mobile below 720 px (single column, no rail, cell = viewport; `EXPANDED_QUERY` and `COLLAPSED_QUERY` in `sk-mission-shell.ts`). Cell width is therefore not monotonic in the viewport across the 720 px edge (719 px gives a cell of 719, 720 px gives 608). The prototype's 620 px toolbar and table breakpoint lies inside the mobile tier, where the cell equals the viewport. TOOLBAR STACK, option C (ruled at CP-1, 2026-10-07): the toolbar stacks under `@container (max-width: 38.75rem)` (620 px) COMBINED with `:host(:state(shell-mobile))`, i.e. only in the shell's mobile tier at a cell of 620 px or less, written as a descendant rule inside the container query (as #5 writes its `:host(:state(shell-mobile))` rules), which gives zero drift against the prototype over the sampled widths (the container-only option A has a 13 px window at 720 to 732 px; the lower-threshold option B fails the 620 px anchor). The `:state(shell-mobile)` custom state comes from #5's `ShellTierController` (`src/shell-tier.ts`, `new ShellTierController(this)` on the screen host), which is used ONLY for this rule: the one-column rule above stays the container pair on `<T>` with no controller. The controller consumes the host's single `attachInternals()`, so the screen (and every part) must not call `attachInternals` anywhere else; a test asserts the state is set in the mobile tier and absent in the others and that the source holds no second `attachInternals` call. S-A6 measured, for each viewport of 689, 719, 720, 732, 799, 800, 801, 831, 832, 1099 and 1100 px (and 1280, 1000, 620), the one tier the shell selects and the cell width, and checks that no mobile-tier cell reaches the two-column threshold; and recorded `<T>` = 45 rem and the stack threshold 38.75 rem here (the measured table is in the WP06 report). The document column carries `min-width: 0`; the prose measure is the E-23 value; tables scroll inside their own box at every width.

## Semantics

Landmarks (one rule, checked in S-A4 and S-A5 before IC-06b freezes the parts by explicit assertions on role, accessible name, landmark and idref, plus a Playwright `ariaSnapshot` (accessibility-tree dump); no axe, no new devDependency, PLAN-FRESH4-003 (b)): the toolbar is a plain `div` with no region role; the file name is NOT a heading (see below) and is a `strong`; the document pane is `role="region"` named `DOCUMENT_LABEL(name)` ("Document: spec.md", a different word from the toolbar's file name, so two landmarks never share a name); the inspector is a `div role="group"` named "Artifact metadata", not an `aside`, because the shell's `main` wraps the whole screen and a complementary landmark inside `main` is not top level (the landmark assertion lists the landmarks inside `main` and expects no `complementary`); facts are a `dl`; linked Work Packages a `ul` of controls, each named by the Work Package title and id (the control is a raw `<button type="button" class="sk-pill-tag">`, S-A4 outcome (c), E-29, ruled at CP-1: a native button, 26 px, ellipsis with the full text in `title`, named by the Work Package title and id).

Scroll regions (PLAN-A11Y-003 (a) and PLAN-A11Y-004 (a), ruled 2026-10-06). A scroll region is a tab stop ONLY WHILE IT OVERFLOWS, and the stop is on the element that actually scrolls (the prototype scrolls `.document-pane`, so the pane, the rendered article, the raw block and each table box are candidates, and only the one whose content exceeds its client size, in the layout at hand, carries `tabindex="0"`). The screen file owns one `OverflowRegion` (the package's existing controller, `src/overflow-region.ts`, extended by IC-06b by ONE named additive edit to several targets and both axes) over those elements: it measures `scrollWidth` and `scrollHeight` against the client size on every update of the screen, on every size change of the targets and once more after the fonts are ready (so content that grows inside a box of unchanged size is seen; there are no timers of the screen's own), and passes the resulting `overflowing` set to the parts; a part draws `tabindex="0"` only for a member. Never overflowing means never a stop, so NFR-003 ("tab stops equal controls shown") is not satisfied by definition: twelve non-overflowing tables add no stop. A table scroll box is `role="region"` with a static positional name from `defaults/` (`TABLE_LABEL(index, total)`, "Table 2 of 5", the position being integers from the model, no document text anywhere in `aria-*`) only while it is a tab stop; otherwise it is a plain `div`. This replaces both earlier statements ("always" and "when scrollable"). Tests: both states for the pane, a table box and the raw block with a positive control (a wide child flips the stop on, removing it flips it off), and a PageDown test that moves `scrollTop` of the element that has the stop. Horizontal keyboard scrolling (S-A2, S-A3): ArrowRight scrolls a focused scroll region 40 px per press; Home, End, PageDown and Space do NOT scroll it horizontally, so a single-line file (a 256 KiB line) is practically unreachable past its first screen by keyboard; the text stays selectable (accepted at CP-1; DA-23).

Tabs: the tablist is `role="tablist"` named "View" with `role="tab"` controls (two when `ArtifactView.tabs` is `two`), each `aria-controls` its panel, selected tab by `aria-selected`; the tab is a native `<button type="button" role="tab">` painted with tokens keyed on `aria-selected` (E-26, the paint entry ruled at CP-1 on the S-A5 evidence; D-13): the library's segmented-choice class is NOT used because its selected look follows `aria-pressed` and never `aria-selected`, and `sk-button role=tab` gives two accessibility nodes per tab. In forced colors the selected tab has a `Highlight` border; a tab is at least 36 px of block size (NFR-015). For `two`, BOTH panels are rendered (the unselected one `hidden`), or `aria-controls` is omitted on the unselected tab, so that no idref dangles (S-A5 found the unselected tab's `aria-controls` dangling in every variant while only one panel was rendered). Per `ArtifactView.tabs`: for `two`, the rendered article and the raw block are `role="tabpanel"` with `aria-labelledby` their tab (ids are static, shadow-root-local, and the fallback case labels its panel by the first tab, which reads "Fallback"; an empty file in the rendered tab keeps the panel and its name); for `none` (a raw-only file) there is no tablist and no tab to name a panel, so the raw block is a `pre` with `aria-label` = `SOURCE_LABEL` ("File source") and carries no `aria-controls` and no `aria-labelledby`. A panel or the raw block is a tab stop only while it overflows (the rule above). A semantics test covers the three cases (two tabs, fallback, none) and asserts that no `aria-labelledby` or `aria-controls` idref is dangling.

Toolbar icon: `renderIcon` of `shell-icons.ts` (the package's local inline icons, G-08) with the `ShellIcon` from `ARTIFACT_KIND_WORDS[kind].icon` (`magnifier` for research, `table` for the data model, `file` for the rest: two additive members added by IC-02), decorative; no new inline svg and no exception.

Headings (PLAN-A11Y-005 (b), ruled 2026-10-06): the file name is NOT a heading: the document's own first `#` is its `h1` (DA-14) and authored levels are kept (FR-006). Where the pane has no `h1` of its own (a raw-only file, the Raw tab, the fallback, the empty file and the loading looks, as `needsHiddenHeading` decides) the screen draws a visually hidden `h1` carrying the file name (`FILE_NAME_LABEL(name)`; the listing loading look, which has no file, carries its loading words from `defaults/`; styled by `src/visually-hidden.ts`, already shared by `sk-phase-bar` and `sk-missions-screen`). Refusal and state titles (refusal, not-found, nothing selected, empty listing, listing and content errors) are `h1` (prototype `05-artifact.html:62`); the inspector's group headings (File, Mission, Linked Work Packages) are `h3` (`:67`). A document with no leading `#`, or with two `#`, is accepted as authored and stated in the PR. A heading-outline test lists the outline for six fixtures (markdown, json, empty, refused, not-found, hostile) and asserts one `h1` in every state except a rendered markdown body. Statuses (kind, refused cause, redaction, unavailable, fallback, selected tab, current tree row) carry text or a non-colour marker in the DOM (NFR-011).

Link controls in the rendered document: an external or artifact link is `<a role="link" tabindex="0">` whose accessible name is its text followed by a visually hidden kind suffix (`LINK_SUFFIX`), an inert link is a `span` with the same suffix rule ("not a followable link") and the destination in `title`; the name is NOT claimed to equal the link text. A test dumps the accessible name and description of an internal, an external and an inert link in one paragraph.

## Announcements (one polite live region; copy in `artifact-copy.ts`)

Keyed on what is shown (selection agreement, above). Listing loading, listing ready ("N artifacts"), listing error, content loading ("Loading <name>"), content ready ("<name> loaded"), refused ("<name> unavailable: <cause>"), error. One test per row of the table in IC-08 and IC-10.

Lifecycle: the live region element is rendered in every state and persists across status changes; its text is REPLACED, never recreated (a region inserted together with its text is often not announced). The first render of a ready state announces nothing. The busy look carries `aria-busy` and adds no second "Loading" announcement. Rapid selection changes coalesce: a selection A then B announces once. When a refusal or error is reached because the user selected another file, the live region carries the one announcement and the pane is not focused (rule 8 moves focus only when the focused control disappears), so the refusal heading and the announcement do not both read. Tests observe the region with a `MutationObserver` (one text change per transition), not a text lookup.

## Behaviour rules (tested)

1. `view` seeds the selected tab (state held in `sk-artifact-screen.ts`, IC-06b: the seed, the reset and the `onSelect` handler); a tab change is internal and emits nothing; a change of the open path resets the tab to `view`.
2. For every non-empty file, the Raw view equals `content` character for character (a test compares `textContent`). An empty file draws the empty-state form ("This file is empty.") in the Raw tab and in the Rendered tab of a markdown file (`data-model.md` rows 9a and 9b); that case has its own assertion and is not an equality test.
3. A refusal or content error pane never contains `content` (a test sets both).
4. Controls that need a Mission id are drawn inert when none exists.
5. Unknown `kind`: raw word, neutral icon, never dropped; unknown `refusalCode`: raw code in the cause, generic sentence, no retry.
6. A `listing` entry for `selectedPath` supplies size and modified; absent, the facts fall back to `content.sizeBytes` and omit Modified.
7. The parse is cached by VALUE of (`content.content`, `content.mediaType`), not by the identity of the `content` object; a property change that does not touch them does not re-parse, and a rebuilt content object with the same string does not either (proved by node identity of an unchanged rendered block, a counted `parseTokens` spy that reads 1 after N property changes leaving `content` unchanged, and the hard-ceiling timing test of IC-10).
8. When the focused control is removed by a state change (Retry activated, a link activation that swaps the content, a tree-driven content swap) the screen moves focus to the document pane: the pane element with `tabindex="-1"` and no id. Mechanism (PLAN-FRESH4-002 (a), ruled 2026-10-06; screen side, no new public member): the focused row of a tree-driven swap lives in the shell's sidebar tree, a sibling in the shell's `sidebar-section` slot and not part of this element, and the tree re-creates its rows in its own update, whose order against the screen's update is undefined, so the screen never decides at update time. In `willUpdate`, on EVERY update (whatever property changed: #5's landing CORR-003 found that a capture limited to named properties misses an update that detaches the focused element, such as a changed `listing`, `workPackages`, `mission` or `vocabulary`), the screen records ONE boolean, whether focus was inside the sidebar tree (`document.activeElement` is, or is inside, an element carrying `slot="sidebar-section"`, as `sk-shell-tree` is when it is a light-DOM child of the shell; a tree in a shadow root is found through the host's `getRootNode()` chain) or inside the pane or its own controls (`this.shadowRoot.activeElement` is the pane or a descendant of it). After `await this.updateComplete` and ONE `requestAnimationFrame` (the tree has then re-rendered), if the boolean is true and `document.activeElement` is `document.body` or null, it calls `focus()` on the pane; in every other case focus is left alone. The flag is dropped when a newer update supersedes it (the last change wins), no timer other than that one frame is used and nothing is observed outside the screen (the tree is neither read nor written). This focus move is its own rule and has no relation to the shell's skip link. Focus elsewhere is left alone (positive control: an element outside the tree and the pane keeps focus across the change; and with focus on `body` before the change, nothing is moved). The pane's ring on programmatic focus is the browser default for `:focus-visible` (E-23 grants the ring properties for keyboard focus).
9. A scroll region (the pane, the rendered article, the raw block, a table box) is a tab stop only while it overflows, on the element that scrolls; the `overflowing` set is fed by the extended `OverflowRegion` of the screen file (see Semantics).
10. The raw and fallback source blocks show a quiet notice (an `sk-notice` of tone `info`) "contains N bidirectional control characters" (N above 0, words and code-point list from `defaults/`) and show the text unchanged; the rendered view shows no notice (R-09, DA-41).
